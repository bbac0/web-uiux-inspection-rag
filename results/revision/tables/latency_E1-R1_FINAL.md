주:

- a 수집 단계에는 프로덕션 코드의 고정 대기 3초(`networkidle` 후 `asyncio.sleep(3)`)가 포함된다.
- b 합계에서 측정한 단계들을 뺀 나머지.
- c **검색 단계 합계(질의 임베딩 + 벡터 검색).** 페이지별로 두 값을 더해 계산하면 평균 0.56초(표준편차 0.23), 중앙값 0.52초,
  P95 0.71초, 최소 0.46초, 최대 3.52초이고 합계 대비 1.9% 다. 평균은 두 단계 평균의 합과 같지만, 중앙값·P95 는 페이지별 합으로 따로
  계산한 값이라 두 행의 중앙값·P95 를 더한 값과 다를 수 있다. P95 는 `latency_table.py` 와 같은 선형 보간 방식이다.
- d **질의 임베딩은 캐시할 수 있다.** E1(고정 질의) 조건의 질의는 모든 페이지에서 같은 문자열 `웹 UI/UX 표준 가이드라인 공통 규정` 이고
  페이지 내용과 무관하다. R1 200페이지 모두 같은 4개 청크가 같은 순서로 검색되었다. 따라서 질의 임베딩은 실행당 한 번 계산해 재사용할 수 있고,
  그러면 페이지당 약 0.55초(합계의 1.8%)가 줄어든다(벡터 검색 결과까지 재사용하면 약 0.56초). 현재 파이프라인은 페이지마다
  임베딩을 다시 호출하며, 실험에서는 프로덕션 코드를 바꾸지 않았으므로 표의 값은 캐시가 없는 상태의 측정값이다.
  페이지별 질의(`--query-mode page`, E3)에서는 질의가 페이지마다 달라 이 캐시가 적용되지 않는다.
