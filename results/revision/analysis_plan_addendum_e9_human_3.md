# 분석 계획 부록 3: E9 사람 평가 범위 축소

작성일: 2026-11-18. 새 시트를 만들기 전, 평가자가 이미 입력한 답을 보기 전에 커밋한다. API 호출 없음.
기존 부록 `analysis_plan_addendum_e9_human.md` (ca021ba)와 `_2.md` (c737a9c)는 고치지 않는다.
이 문서에 적지 않은 내용은 기존 부록을 그대로 따른다.

## 1. 변경 사유

- 평가자 A 의 시간이 부족하다. 본 평가 범위를 정규식(주 지표)에 걸린 이슈 52건으로 줄인다.
- 안 걸린 이슈 86건의 평가와 재평가 20건(부록 2 3절)은 실시하지 않는다. A 자기 일치도는 보고하지 않는다.

## 2. 표본과 시트

- 표본: `e9_eval/key/sample_selection.csv` (93f2542) 중 `regex_stratum = hit` 인 52건 전수. 새로 뽑지 않는다.
- 시트 `e9_eval/rater_A_e9_hit52/`: 열, 값, 지침은 부록 2 4절과 같다.
- 행 순서: `e9_eval/key/e9_key.csv` 의 행 순서로 52건을 놓고 `random.Random(20261207).shuffle`.
- issue_id 는 기존 시트(`rater_A_e9/`)와 같게 둔다(이미 입력한 답을 옮기기 위해). 스크린샷 파일명은 새 토큰이다.
- 정답 라벨, 조건, 정규식 결과, 층은 `e9_eval/key/` 에만 둔다.

## 3. 이미 입력한 9건

- A 가 `rater_A_e9/` 시트에 입력해 저장한 9건(`rater_A_e9_partial9.csv`) 중 52건에 드는 건은
  답을 바꾸지 않고 새 시트의 같은 issue_id 로 옮긴다. 분석에는 A 가 새 시트에서 내보낸 최종 CSV 를 쓴다.
- 52건에 들지 않는 건(안 걸린 이슈)은 분석에 쓰지 않고 별도 목록에 보관만 한다. 보고서에는 건수만 적는다.

## 4. 분석 (바뀐 부분)

- 보고 지표는 정규식 정밀도(걸린 이슈 중 A 가 실제 결함으로 본 비율) 하나다.
- 단위: (이슈, 정규식 주 지표가 잡은 유형) 쌍. 그 유형에 대응하는 열(E9-1 → banner-text, E9-2 → spec-values,
  E9-3 → login-address)이 '예'이면 A 가 실제 결함으로 본 것으로 센다. 두 유형이 잡힌 이슈는 쌍이 두 개다.
- 층: 조건 run × 페이지 결함 유형(E9-1, E9-2, E9-3, 대조군) × 잡은 유형. 층별로 "n쌍 중 m쌍"을 적는다.
- 걸린 이슈는 전수이므로 조건 run × 잡은 유형 합계도 적는다. 신뢰구간과 검정은 내지 않는다.
- 판정 열이 빈 칸인 쌍은 분모에서 빼고 그 수를 따로 적는다.
- 보조 규칙(aux_*)은 표본이 주 지표 기준이라 이번 보고에서 쓰지 않는다.

## 5. 한계 (보고서에 적는다)

- 재현 누락(정규식이 놓친 실제 결함)은 사람이 검증하지 않았다. 정규식의 재현율에 대한 사람 근거는 없다.
- 사람 기준은 평가자 A 1인이며 재평가가 없어 자기 일치도도 없다.
- 일부 층은 1~3쌍이라 비율이 아니라 건수로만 읽어야 한다.
- 옮긴 답은 기존 시트의 다른 행 순서와 맥락에서 입력되었다.
