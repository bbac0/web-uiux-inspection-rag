# E9 분석 계획 (사전 지정, `exp-freeze-e9-v1`)

- 작성 2026-11-13. 근거: `docs/e9_design.md` v5 (2026-11-13 생성기 승인 반영). **E9 에 API 를 쓰기 전에** 동결한다.
- **사전 수정 (`exp-freeze-e9-v2`, 2026-11-13, E9 API 호출 전·파일럿 전):** 연구자 결정으로 3.1a 보조 분석(E9-1 변형 문구 전체 적용)을 추가했다.
  주 지표 규칙은 바꾸지 않았다. 파일럿 절(design §5.1)도 추가했다.
- **사전 수정 (`exp-freeze-e9-v4`, 2026-11-13, 본 실험 1·2회차 결과를 본 뒤, 3회째 실행 전):** 연구자 결정. 1·2회차 결과(`results/revision/reports/e9_main_report.md`)는 이미 보았고 3회째 결과는 아직 없다. 정규식 규칙·판정 프롬프트·주입 코드·조건 입력은 바꾸지 않았다.
  - (a) 반복 규칙은 '다섯 조건 모두 3회째'로 정의되어 있으나, 규칙이 발동한 비교 쌍이 fixed-long vs RAG 끔(E9-1, E9-2, E9-3 세 건 모두)이므로 **이 두 조건에서만 3회째를 실행**한다(run_id `e9-main-fixedlong-r3`, `e9-main-norag-r3`). 나머지 세 조건(고정 질의, 페이지별 질의, 관련 조항 제공)은 2회로 보고한다. 이유: 관련 조항 제공과 다른 조건의 탐지율 차이(E9-2 1.000 대 0.033~0.133, E9-3 1.000 대 0.067~0.333)가 이미 실행 간 차이보다 크고, 발동한 세 건은 모두 fixed-long vs RAG 끔 쌍이었다. 예산 제약(연구 총액 5만 원)도 있다.
  - (b) D_run(t) 은 기존 정의(다섯 조건 중 실행 간 탐지율 차이의 최댓값)를 그대로 쓰되, fixed-long 과 RAG 끔은 3회 중 최대 차이(최댓값 − 최솟값), 나머지 세 조건은 |1회차 − 2회차| 를 쓴다. fixed-long vs RAG 끔 쌍의 D_cond(t) 는 두 조건의 **3회 평균** 탐지율 차이의 절댓값이다. 이 계산으로 D_cond < D_run 여부를 보고하되, 결과와 상관없이 4회째는 하지 않는다(최대 3회 유지). 이 정의는 3회째 결과를 보기 전에 적었다.
  - (c) E9 LLM 판정(3.2)과 E9-4 보조(390x844) 실행은 예산 제약으로 **수행하지 않는다.** 주 지표는 결정적 정규식이며, 사람 평가(§5, 약 30페이지)로 정규식의 정확도를 확인하는 계획은 유지한다(§5 의 LLM 판정 비교 부분은 해당 없음). §6 한계에 적었다.
- 이 문서는 실행 후 수정하지 않는다. 계획과 다르게 해야 할 일이 생기면 `results/revision/README.md` 의 계획 이탈 기록에 적는다.
- 결과가 어느 방향으로 나와도 그대로 보고한다. 결정적 규칙, 판정 프롬프트, 조건 입력은 결과를 본 뒤 바꾸지 않는다.

## 2. 조건과 실행 (`results/revision/e9/conditions_e9.json`)

- 5조건: RAG 끔, 고정 질의(K=4), 페이지별 질의, 관련 조항 제공(related-clause, 6청크 `e9_related_clause_chunks.csv`),
  fixed-long(E9 결함 주제 키워드를 제외한 컨텍스트, 9청크 4,465자 `e9_fixed_long_chunks.csv`, `fixed_long_selection.json`).
  다섯 조건 모두 91페이지 전체, 모든 페이지에 같은 청크·같은 순서(라벨 누출 방지).
- 공통: 러너 `experiments/revision/run_experiment_e9.py`(동결 러너 래퍼), 프로덕션 프롬프트·모델(gemini-2.5-flash)·temperature 0·1280x800·
  렌더링 HTML 앞 5,000자, `--max-pages 1`, 프롬프트 날짜 2026-11-11(기존 모든 run 과 같은 날짜).
- 반복: **2회로 시작.** 3회째 규칙(사전 지정, §6.1 결정적 규칙의 페이지 단위 유형별 탐지율, 주 지표 대상 E9-1·E9-2·E9-3):
  - 비교 쌍 4개: 관련 조항 제공 vs RAG 끔, 관련 조항 제공 vs 고정 질의, 관련 조항 제공 vs fixed-long, fixed-long vs RAG 끔.
  - D_cond(t, 쌍) = |두 조건 탐지율 차이| (두 실행 평균), D_run(t) = 다섯 조건 중 |1회차 − 2회차 탐지율| 의 최댓값.
  - 주 지표 유형 t 와 비교 쌍 중 하나라도 D_cond(t, 쌍) < D_run(t) 이면 3회째를 다섯 조건 모두에서 실행한다. 3회째는 그대로 포함하고 규칙을 다시 적용하지 않는다(최대 3회).
- 보조 E9-4: 1280x800 실행에는 포함하되 주 지표에서 제외. 별도로 390x844 실행(E9-4 15 + 대조군 30, `e9_aux390_pages.txt`, 5조건, 반복 1회).

## 3. 채점

### 3.1 주 지표: 결정적 정규식 규칙 (`scoring/e9_rules.py`, design §6.1 그대로)

- 대상 페이지 이슈: description 의 `[URL]` 접두어가 그 페이지(`/{page_id}.html`)인 이슈.
- 이슈 텍스트 = description(접두어 제거) + 공백 + suggestion. 대소문자 무시, 패턴의 `\s*` 만 공백 허용.
- 유형별로 조건을 만족하는 이슈가 1건 이상이면 그 페이지에서 탐지.
- **E9-1 '주입된 변형 문구' 절의 해석:** 그 페이지에 실제로 주입된 문구로 해석한다(design §6.1 문구 그대로). E9-1 결함 페이지가 아니면 이 절은 적용되지 않는다.
  정확 문자열 비교는 공백을 정규화하지 않는다.

### 3.1a 보조 분석: E9-1 변형 문구 전체 적용 (사전 지정, `exp-freeze-e9-v2`)

- 주 지표(3.1)는 그대로다. 보조 분석은 E9-1 의 '주입된 변형 문구' 절만 바꾼다: **E9-1 결함 페이지인지와 관계없이 모든 페이지에서**
  6개 변형 문구(E9-1a 3개, E9-1b 3개; `e9_generate.py` 의 E9_1A, E9_1B) 중 하나라도 이슈 텍스트에 정확히(공백 정규화 없음, 끝 마침표 제외) 들어 있으면
  E9-1 탐지로 본다. 주제어 절과 규정 문구 인용 절, 그리고 E9-2·E9-3·E9-4 규칙은 주 지표와 같다.
- 구현: `scoring/e9_rules_aux.py` (동결된 `scoring/e9_rules.py` 를 import, 수정하지 않음).
- 출력: `experiments/revision/e9_regex_table.py` 가 주 지표와 보조 분석을 **같은 표에 나란히** 낸다
  (조건 × 유형 × 규칙별 결함 페이지 탐지 수·재현율, 대조군 탐지 수·위양성률; E9-1 은 강도 a·b 별도 행).
- 해석: 두 방식의 차이는 related-clause 조건에서 조항 청크의 미준수 사례 문구("대한민국 공식 전자정부 웹사이트입니다.")를 결함 없는 페이지에서
  인용하는 경우처럼, 그 페이지에 없는 변형 문구를 인용한 이슈에서만 생긴다. 이 규칙도 결과를 본 뒤 바꾸지 않는다.

### 3.2 보조: LLM 판정 (`scoring/e9_judge_prompt.py` = `docs/e9_judge_prompt_draft.md` 승인 전문)

- 이슈 문구가 어떤 점검 항목을 지적하는지의 **분류**(결함 실재 판단 아님). 다중 라벨, 페이지 단위는 항목별 '예' 이슈가 1건 이상이면 탐지.
- 설정: `scoring/grader_config.json` 과 같음(claude-sonnet-5-5, thinking between_tools, effort high, max_tokens 100, temperature 미지정, fallback 없음).
- **pass1 만** 수행(본 실험 2회, 규칙 발동 시 3회째). **E9-4 보조(390x844)는 결정적 규칙만**, 의미 채점 없음.
- 채점 경로(표준/배치)는 본 실험과 같은 사전 규칙(analysis_plan 10절 12항).

## 4. 지표와 검정

- 주 지표 대상(E9-1, E9-2, E9-3)의 결함 유형 × 조건별 재현율, 대조군 위양성률, 셀 단위 정밀도·특이도·균형 정확도·MCC. E9-1 은 강도 a·b 별로도 보고.
  E9-2 는 영역(배너·헤더·푸터)별로도 병기.
- '구조적 탐지 불가'(design §3) 결함은 따로 층화해 병기(현재 0페이지).
- 조건 간 쌍 비교: exact McNemar 4개(관련 조항 제공 vs RAG 끔, 관련 조항 제공 vs 고정 질의, 관련 조항 제공 vs fixed-long, fixed-long vs RAG 끔), Holm 보정(4개 검정).
  관련 조항 제공 vs fixed-long = '조항 내용' 효과, fixed-long vs RAG 끔 = '컨텍스트 길이(와 키워드 제외 일반 조항)' 효과.

## 5. 사람 평가 (design §6.3, §6.5)

- 표본: 고정 질의 조건과 관련 조항 제공 조건(1회차)의 이슈 중 결함 유형별 5페이지(E9-1 은 1a·1b 각 3) + 대조군 10페이지 ≈ 31페이지 × 2조건의 이슈 전체.
  층화 기준은 결함 유형·강도와 대조군 여부뿐. **표본 추출 시드 20261114.**
- 평가자 2명 공동 평가, 불일치는 중재자 1명(주입 라벨·조건·채점 결과를 보지 않음). 질문: 4개 항목 예/아니오 + 해당 없음, 코드에 존재하는가, 화면에서 보이는가, 비고.
- 사람 판정(합의 + 중재)을 기준 표준으로 (1) 결정적 정규식 규칙, (2) LLM 판정 각각의 이슈 단위 정확도·재현율·정밀도·Cohen's kappa 를 **따로** 계산해 나란히 보고하고,
  두 방식의 불일치 사례(정규식만 예, LLM 만 예)를 목록으로 낸다. 결과를 보고 규칙이나 프롬프트를 바꾸지 않는다.

## 6. 해석과 한계 (design §6.5, §6.6)

- (`exp-freeze-e9-v4` 사전 수정) 예산 제약(연구 총액 5만 원)으로 E9 LLM 판정과 E9-4 보조(390x844)를 하지 않았다. 주 지표는 정규식 하나뿐이며 그 정확도는 사람 평가(약 30페이지)로만 확인한다. 3회째는 fixed-long 과 RAG 끔에서만 실행해 조건마다 반복 수가 다르다(2회 또는 3회).
- 관련 조항 제공 조건은 RAG 에 가장 유리한 **상한(upper bound)** 조건이다(정답 문자열과 규정값을 직접 규정한 조항을 모든 페이지에 준다).
- 정규식 규칙은 구체 문구 없이 일반적으로만 지적한 이슈를 놓칠 수 있고(위음성), 주제어가 우연히 함께 나온 이슈를 셀 수 있다(위양성).
- 본문 재사용 시 faq·terms·contact 템플릿의 본문 로그인 링크를 지웠다(design §6.5). portal_main 본문의 '배너' 단어, login_page 본문의 '로그인' 은 그대로다.
