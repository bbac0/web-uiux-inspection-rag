- 작성: 2026-11-11, 1단계 (모든 API 실행 전). git tag `exp-freeze-v1` 로 동결한다.
- 개정: 2026-11-11, API 호출 전 사용자 승인으로 2절(기준 표준 문장)과 5절(cached 단가)을 보완하고 `exp-freeze-v2` 로 다시 동결했다.
- **사전 지정 추가, 2026-11-12, `exp-freeze-v5`:** E1/E2-A1 생성 실행 후, 의미 채점과 나머지 조건 실행 전에 10절을 추가하고 4·5절의 E3 명칭을 바꿨다.

  실행 간 변동 큼, 채점기 간 불일치 등)도 표에서 빼지 않는다. 지표 정의, 채점 기준, 키워드 사전, 채점 프롬프트는
  결과를 본 뒤 바꾸지 않는다.

## 1. 데이터와 정답

- 테스트베드: `testbed_200/` 200페이지 (결함 161, 대조군 39), 템플릿 10개 × 20페이지. 파일 해시는
  `testbed_manifest.csv`. 재생성하지 않는다.
- 결함 유형 5개: Poor Contrast Ratio, Mobile Layout Breakage, Button Area Clipping,
  Standard Terminology Violation, Duplicate ID Markup Error.
- **정답 라벨은 두 벌이다.**
  - `nominal`: `dataset_metadata.json` 의 주입 기록 그대로.
  - `effective`: E0 결정적 검사로 렌더링에서 효과가 확인된 것. 모든 200페이지에 같은 검사를 적용한다
    (대조군도 검사하며, 대조군에서 양성이 나오면 그대로 보고한다).
    | 유형 | effective = 1 조건 |
    |---|---|
    | Contrast | 보이는 텍스트 요소 중 계산된 스타일의 WCAG 대비비가 4.5:1 미만인 요소가 있음 |
    | Mobile (1280) | 1280x800 에서 `document.documentElement.scrollWidth > window.innerWidth` |
    | Mobile (390) | 390x844 에서 같은 조건 |
    | Button | `button`, `input[type=submit|button|reset]` 중 렌더링 높이 ≤ 4px 이거나 계산된 font-size 가 0 인 요소가 있음 (버튼이 없으면 0) |
    | Terminology | 렌더링된 DOM(제목 포함) 텍스트에 주입 문자열 `접속하기` 가 있음 |
    | Duplicate ID | 같은 `id` 값을 가진 요소가 2개 이상 있음 (비가시 결함임을 별도 표시) |
  - Mobile 의 effective 라벨은 run 의 뷰포트에 맞춘다: E1·E2·E3 는 1280, E4 는 390.
- **모든 지표를 nominal 과 effective 두 가지로 계산해 함께 보고한다.** 둘 중 하나만 고르지 않는다.

## 2. 분석 단위와 예측

- 분석 단위: 페이지 × 유형 셀 (run 당 200 × 5 = 1,000셀; 하위 집합 실험은 해당 페이지 수 × 5).
- 셀 예측 = 1: 해당 페이지 리포트의 대상 페이지 이슈(description 에 `testbed_200/{page_id}.html` 포함) 중
  채점기가 그 유형으로 분류한 이슈가 1건 이상.
- 채점기
  1. **주 채점기: 의미 채점** — Gemini 가 아닌 모델 계열, 기존 `experiments/semantic_issue_classifier.py` 의
     `JUDGE_PROMPT`(v1) 범주 정의를 그대로 쓰고 입력도 기존과 같이 이슈 description 만 넣는다. 프로바이더는 4단계에서 정한다.
     temperature 0, 모델 버전 문자열 기록.
  2. **보조 채점기: 키워드 사전** — `evaluate_performance_v5.py` 의 `CATEGORY_PHRASES` (수정 없음, 다중 라벨).
     논문 1차 결과와 비교하기 위해 보고한다.
  3. 사람 평가(E5)는 위 두 채점기의 타당도 검증에 쓴다 (전체 지표를 대체하지 않는다).
  - **사람 평가 부분집합이 기준(reference standard)이고, 의미 채점과 키워드 채점은 둘 다 사람 판정과 비교해서 같은 비중으로 보고한다.**
    '주 채점기'는 200페이지 전체 지표를 계산할 때 어느 채점기의 표를 먼저 싣는지만 정한다. 사람 판정과의 일치도 표에서는
    두 채점기를 같은 표, 같은 지표로 나란히 보고하고 어느 한쪽을 빼거나 축약하지 않는다.
- 실패 처리: API 오류, RAG 0청크, 수집 오류, 파싱 실패 페이지는 **분석에서 빼지 않는다**.
  주 분석에서는 그 페이지의 모든 셀을 예측 0(미탐지)으로 두고, 민감도 분석에서는 해당 페이지를 제외한다.
  오류 페이지 수는 조건별로 따로 표에 적는다.

## 3. 주 지표

셀 단위 이진 분류의 다음 지표를 5개 유형 통합(micro, 셀 풀링)과 유형별로 계산한다.

- 정밀도 = TP/(TP+FP), 재현율 = TP/(TP+FN), 특이도 = TN/(TN+FP),
  균형 정확도 = (재현율+특이도)/2, MCC.
- 분모가 0이면 값을 비워 두고 "정의되지 않음"으로 표시한다.
- 병기: 기존 논문 방식의 페이지 단위 결과("아무 유형이나 맞으면 TP", 결함 페이지 vs 대조군) —
  정밀도, 재현율, F1, 위양성률.

## 5. 통계 방법

- **신뢰구간: 템플릿 군집 부트스트랩.** 10개 템플릿을 복원 추출(군집 안의 페이지·셀은 통째로), B = 10,000,
  난수 시드 20261111 (numpy `default_rng`), 백분위수 95% CI. 쌍 비교의 차이는 같은 템플릿 추출로 두 조건을 함께 재표본화한다.
  군집이 10개뿐이라 CI 가 좁게 나올 수 있음을 한계로 적는다.
- **Leave-one-template-out (LOTO):** 템플릿 하나씩 빼고 지표를 다시 계산해 10개 값의 범위와 jackknife 표준오차를 보고한다.
- **쌍 비교: exact McNemar** (불일치 쌍에 대한 양측 이항 검정). 셀 단위 정오(예측 = 정답 여부)로 검정한다.
  - E2: A1, A2, A3 각각 vs E1-R1, 5유형 통합 1회씩 = 3개 검정을 Holm 보정. 유형별 검정은 탐색적(보정 없음, 그렇게 표시).
  - E3: 용어 유형 셀(84페이지)에서 fixed–page, fixed–related-clause, page–related-clause 3개 검정 Holm 보정 (v5 수정: 'oracle' → 'related-clause').
    대조군 39페이지의 용어 위양성은 따로 표로 보고한다.
    fixed 는 E1-R1 을 재사용하므로 조건 차이와 실행 간 변동이 섞인다. 이를 E1 R1~R3 변동 폭과 나란히 해석한다.
  - E4: 모바일 유형 셀 vs E1-R1 같은 페이지, 1개 검정.
  - 검정 결과는 p 값과 함께 불일치 쌍 수(b, c)와 효과 크기(지표 차이와 CI)를 같이 보고한다.
- **실행 간 변동성 (E1 R1~R3):** 유형별 탐지 셀 수의 평균과 표준편차, 3회 모두 같은 예측을 낸 셀 비율,
  Fleiss' kappa(3회), 쌍별 Cohen's kappa.
- **점수 (Eq. 3):** 저장된 리포트에서 정수 나눗셈(`//`, 페이지 간 평균)을 반올림으로 바꿔 다시 계산한다.
  `--max-pages 1` 에서는 평균할 페이지가 하나라 두 방식의 값이 같다는 점을 함께 적는다. 결함 페이지와 대조군의
  분리도를 AUC(Mann–Whitney)로 보고하며, 페이지 점수는 3개 범주 점수의 평균과 최솟값 두 가지로 계산한다
  (CI 는 템플릿 군집 부트스트랩). 대상은 E1-R1 과 레거시 run2. N 을 결정적 값으로 바꾸는 방안은 구현하지 않고
  제안서(`docs/score_proposal.md`)만 쓴다.
- **지연시간:** E1-R1(순차) 로그로 수집, 질의 임베딩, 벡터 검색, 이미지 업로드, LLM, 합계의 평균, 표준편차, 중앙값, P95.
- **비용:** 호출당 입력, cached, 출력, derived 사고 토큰과 비용(cached 입력 $0.03/1M, 나머지 입력 $0.30/1M, 출력+사고 $2.50/1M; cached 구간은 따로 기록), run 별 합계.

## 6. 사람 평가 (E5)

- 평가 항목: 이슈 분류 6개(5개 유형 + 해당 없음), 그리고 존재 여부를 두 질문으로 나눠 묻는다 (9절 사전 수정):
  (a) 해당 결함이 코드(HTML/CSS)에 존재하는가, (b) 해당 결함이 렌더링된 화면에서 눈으로 확인되는가 (각각 예/아니오/판단 불가).
  예: 버튼이 없는 페이지에 버튼 CSS 규칙만 있는 경우 (a) 예 (b) 아니오, 화면에 보이지 않는 중복 ID 는 (a) 예 (b) 아니오.
- 분석: 평가자 간 Cohen's kappa; 두 평가자가 같은 항목만 합의 라벨로 쓰고 불일치는 별도 목록으로 낸다.
  사람 합의 vs 키워드, 사람 합의 vs 의미 채점의 kappa와 유형별 혼동행렬. 불일치 사례(특히 표준 용어 위반) 목록.

## 9. 사전 수정 (pre-execution amendment) — 2026-11-12, `exp-freeze-v4`

본 실험 API 실행 전(파일럿 pilot-01, pilot-02 만 실행된 상태)에 사용자 결정으로 다음을 바꿨다. 1~8절의 다른 내용은 그대로다.

1. **E2-A1(`--no-rag`)을 1회에서 3회(A1-1, A1-2, A1-3)로 늘린다.** 이유: 레거시 두 실행(run1, run2) 사이에서 유형별 탐지 수가
   최대 3페이지 차이가 났다. E1 과 같은 횟수(3회)로 맞춰야 RAG 켬/끔 차이를 실행 간 변동과 비교할 수 있다. A2, A3 는 각 1회 그대로.
   - 실행 순서: E1-R1(순차) → A1-1 → R2 → A1-2 → R3 → A1-3 (교차 실행, 각 run 동시 4건 이하). R1 의 오류율이 5% 이하이고
     파싱 실패가 2% 이하일 때만 이어서 실행한다.
   - 분석: (i) 주 검정은 계획대로 E1-R1 vs A1-1 exact McNemar 이고, A2·A3 와 함께 Holm 보정 3개 검정 가족에 넣는다.
     (ii) 같은 순번 쌍 R2–A1-2, R3–A1-3 의 McNemar 를 보조로 보고한다. (iii) 조건별 3회 다수결 예측(3회 중 2회 이상 탐지된 셀)끼리
     McNemar 를 강건성 분석으로 보고한다. (iv) 유형별 탐지 셀 수의 조건 간 평균 차이를 각 조건 안의 실행 간 표준편차·범위와 나란히 보고한다.
     (v) 3회 × 3회 실행 쌍 9개의 차이 분포를 기술 통계로 보고한다.
