# E9 설계: 가이드라인 조항에 직접 근거한 결정적 결함 (설계 초안 v3)

- 작성 2026-11-12, 2026-11-13 생성기 승인(시드 20261116, 본문 로그인 링크 제거 규칙 확정; §6.5), 파일럿 후 입력 수정 v3(§5.2) (v5: fixed-long 제외 규칙 확대, 한계·해석 절 추가, 의미 채점 범위 축소에 따른 비용 재계산. v4: fixed-long 조건 추가. v3: 연구자 검토 a~h 반영). **설계만 있다.** 생성기·실행·채점 코드는 연구자가 이 문서를 다시 검토하고 승인한 뒤 작성한다. API 호출 없음.
- 만들 위치: 별도 디렉터리 **`testbed_e9/`**, 별도 동결 태그 **`exp-freeze-e9-v1`**. 기존 `testbed_200/` 과 그 결과에는 섞지 않는다.
- 조항 원문과 청크 ID 는 `services/chroma_db`(1,020청크)를 sqlite 읽기 전용으로 열어 확인했다.

## 0. 왜 E9 인가

기존 테스트베드의 표준 용어 위반(`로그인` → `접속하기`)은 색인된 문서에 직접 근거 조항이 없다(gov_check 208쪽 로그인 항목은 링크의 목적지를 규정).
E9 는 색인된 문서에 **규범형으로 명시**되어 있고 **결정적으로 검증할 수 있는** 조항만 골라 그 조항을 위반하는 결함을 주입한다.
이를 통해 RAG 가 '가이드라인 근거 결함'을 찾는 데 실제로 기여하는지를 시험한다.

## 2. 기준 페이지

기존 10개 템플릿 확인 결과: 공식 배너 0/10, `<footer>` 0/10, `<header>` 7/10(규격 스타일 없음), 로그인 링크 9/10.
→ **기준 페이지를 새로 만든다.**

- 골격(순서 고정): `<head>` 안의 짧은 `<style>` 블록(규격값) → `<body>` 첫 요소 공식 배너 → 규격 헤더(유틸리티 링크, 로그인 링크, 메인 메뉴) →
  본문(기존 10개 템플릿의 `<main>` 내용 재사용) → 규격 푸터(연락처, 유틸리티·정책 링크, 저작권).
- **배너와 헤더 마크업이 렌더링 HTML 앞 5,000자 안에 오도록** `<style>` 블록 길이를 포함해 설계한다(목표: `<style>` ≤ 1,500자, 배너+헤더 끝 오프셋 ≤ 3,000자).
- 본문은 짧게 유지해 푸터가 가능하면 1280x800 뷰포트 안과 앞 5,000자 안에 들어오게 한다. 들어오지 않는 본문 템플릿은 푸터 결함 배정에서 제외한다.
- 서체 pretendardGOV 는 글꼴 파일 없이 선언만 한다(검증은 선언된 font-family 문자열).
- 테스트베드 서버 루트에 `/login`, `/signup` 페이지를 둔다(E9-3 검증과 크롤 404 방지).

**대조군:** 결함을 넣지 않은 기준 페이지. 올바른 배너 문구, 배너·헤더·푸터 규격값, 로그인 href `/login`, 1280·768·390px 모두에서
로그인 링크가 보임을 **결정적 검사로 모두 통과해야** 대조군으로 인정한다. 결함 페이지는 주입한 위반 하나만 실패하고 나머지는 통과해야 한다.
결과는 `ground_truth_e9.csv`(page_id, 본문 템플릿, 결함 ID, 강도, 주입 문자열, 검증 통과 여부, §3 탐지 가능성 열)에 기록한다.

## 3. 탐지 가능성 사전 검증 (결정적, 생성 직후)

시스템 입력과 같은 조건(Playwright, 1280x800, `networkidle` 후 3초)으로 각 페이지를 열어 다음을 기록한다.

| 열 | 정의 |
|---|---|
| `inj_offset_start`, `inj_offset_end` | 렌더링 HTML(`page.content()`)에서 주입 문자열의 위치. 주입 문자열 = E9-1 바뀐 배너 문구, E9-2 바뀐 CSS 선언(예: `font-size: 14px`)이 들어간 위치(`<style>` 블록이면 그 선언, 인라인이면 속성), E9-3 `href="/signup"`, E9-4 media query 문자열 |
| `in_first_5000` | `inj_offset_end ≤ 5000` (시스템이 HTML 앞 5,000자만 보기 때문) |
| `in_viewport_1280x800` | 결함이 걸린 요소의 `getBoundingClientRect()` 가 0 ≤ x < 1280, 0 ≤ y < 800 범위와 겹치고 보이는가 (E9-3·E9-4 는 요소 자체의 위치를 기록) |
| `structurally_undetectable` | `in_first_5000` 이 거짓**이거나** `in_viewport_1280x800` 이 거짓이면 참 |

- '구조적 탐지 불가' 결함은 분석에서 **따로 층화**한다(주 지표는 탐지 가능 결함만, 층별 표 병기).
- **푸터 결함은 두 검사를 모두 통과하는 경우만 포함한다.** 통과하지 못하는 배정은 생성 단계에서 다른 본문 템플릿으로 다시 배정한다(시드 고정, 재배정 기록).
- E9-3(화면에 안 보이는 목적지 결함)과 E9-4(1280 에서 안 보이는 결함)는 정의상 화면만으로는 탐지 불가이므로, '뷰포트 안'은 해당 링크 요소가 보이는지로 기록하고 해석은 표에 따로 적는다.

## 4. RAG 조건과 관련 조항 제공

조건 5개: (1) RAG 끔, (2) 고정 질의(K=4), (3) 페이지별 질의, (4) 관련 조항 제공(related-clause, 코드 플래그 `--query-mode oracle`),
(5) **E9 결함 주제 키워드를 제외한 컨텍스트, 길이 맞춤(fixed-long)**. 다섯 조건 모두 91페이지 전체에 적용한다.

**관련 조항 제공 조건은 모든 페이지(결함·대조군 모두)에 같은 청크 세트를 같은 순서로 준다.** 페이지 라벨에 따라 청크를 달리 주지 않는다(라벨 누출 방지).
청크 세트 = E9 결함 조항 청크 전부:

### 4.1 fixed-long 조건 (사전 지정)

- 목표 길이 T = 관련 조항 6청크 컨텍스트의 프롬프트 형태 길이 **4,538자**. 허용 범위 ±10% = **4,084~4,992자**.
- 고정 질의("웹 UI/UX 표준 가이드라인 공통 규정")로 1,020청크 전체의 순위를 매긴다(프로덕션과 같은 `embed_query` + L2 거리).
- **제외 규칙 (2026-11-12 사전 지정, 키워드 목록은 연구자 확정, 실행 후 수정하지 않음):** 다음 청크를 순위에서 모두 뺀다.
  - (a) E9 관련 조항 6청크(§4 표).
  - (b) 다음 키워드 중 하나라도 본문에 포함된 모든 청크: "공식 배너", "공식 전자정부 누리집", "배너", "헤더", "푸터", "로그인", "회원가입", "작은 화면", "768px".
    키워드 검사는 청크 본문 원문에 대한 부분 문자열 일치로 한다(대소문자 구분 없음). PDF 추출 텍스트의 글자 사이 공백 때문에 놓치는 경우를 막기 위해
    본문과 키워드 모두 공백을 지운 문자열로도 한 번 더 검사하고, 둘 중 하나라도 걸리면 제외한다. (헤더·푸터는 E9-2 규격값 조항과 관련된 주제어다.)
- **K 결정:** 제외 후 남은 청크를 고정 질의 거리 순으로 세우고(필터된 순위), 위에서부터 더해 프롬프트 형태 길이가 허용 범위(4,084~4,992자)에
  처음 들어가는 가장 작은 K 를 쓴다. 범위에 들어가는 K 가 없으면 |길이 − T| 가 가장 작은 K 를 쓴다.
- **기록(`fixed_long_selection.json`):** 고정 질의 임베딩 호출 기록, 제외된 청크 수와 ID(제외 사유 (a) 또는 키워드), 키워드별 제외 건수,
  필터된 순위 상위 K 의 청크 ID·원래 순위·거리·길이, 최종 컨텍스트 길이. 제외 규칙은 결과를 본 뒤에 바꾸지 않는다.
- **K 추정:** 1,020청크의 프롬프트 형태 평균 길이(머리글·구분자 포함 약 471자)로 보면 K = 9~10. 제외로 순위가 바뀌므로 **정확한 K 는 고정 질의 임베딩 1회 호출로
  순위를 얻은 뒤 확정한다.**
  이 호출은 R1~A1 종료 후 연구자 승인으로 이미 계획된 1회(gov_check 청크 최상위 순위 계산)와 같은 호출을 쓴다(호출은 로그에 남김).
- **구현 방식(코드 변경 없음):** 고정 질의는 페이지와 무관하므로 선택된 K개 청크 목록이 모든 페이지에서 같다. 이 목록을 관련 조항 제공과 같은 입력 형식
  (`page_id,chunk_id` CSV, 모든 페이지에 같은 청크·같은 순서)으로 만들어 `--query-mode oracle` 로 넣는다. 순위와 거리는 `fixed_long_selection.json` 에 별도로 남긴다.
- **사전 집계 (순위와 무관한 정적 집계, API 없음, 2026-11-12):** 키워드 규칙으로 1,020청크 중 **170개**가 제외된다
  (키워드별: 공식 배너 27, 공식 전자정부 누리집 3, 배너 50, 헤더 73, 푸터 41, 로그인 27, 회원가입 10, 작은 화면 28, 768px 17; 한 청크가 여러 키워드에 걸릴 수 있음).
  **현재 고정 질의 상위 4청크 중 2개(gov_guide 15쪽 `ffd48677-a4cc-405b-aacd-15820a7f65f0`, 218쪽 `654c214c-448d-4030-862a-67c5899520ca`)도
  '공식 배너·배너·헤더·푸터'로 제외된다.** 따라서 fixed-long 은 고정 질의(K=4)의 상위 청크를 그대로 포함하지 않으며, 두 조건은 길이뿐 아니라 내용도 다르다.
- **공백 무시 검사(설계자 추가, 연구자 확인 필요):** 원문 부분 문자열 검사만 하면 169개, 공백을 지운 문자열 검사를 더하면 170개다.
  차이는 1청크(gov_guide 330쪽 `77168bc0-3d50-41ec-84f0-b879e49a3e2c`)뿐이다. 연구자가 키워드 '본문에 포함'을 원문 부분 문자열로만 정하면 이 항목을 지운다.
- **명칭:** 이 조건은 "무관한 컨텍스트"가 아니라 **"E9 결함 주제 키워드를 제외한 컨텍스트"** 로 서술한다. 키워드에 걸리지 않는 일반 UI/UX 조항
  (예: 명도 대비, 링크 레이블)은 남을 수 있으며, 이는 '결함 주제와 무관'을 보장하지 않는다.

## 5. 규모와 반복 규칙

- 페이지: E9-1 16(1a 8 + 1b 8), E9-2 15, E9-3 15, E9-4 15(보조) = 결함 61 + 대조군 30 = **91페이지**. 결함은 페이지당 1종, 본문 템플릿 10종에 고르게 배정.
- 조건: 5개(§4), 모든 페이지에 적용.
- **반복: 2회로 시작한다.** 3회째 실행 규칙(사전 지정):
  - 비교 지표 = **유형별 탐지율**(결정적 규칙 §6.1 로 계산한 페이지 단위 탐지율, 주 지표 대상 E9-1·E9-2·E9-3).
  - 비교 쌍(4개): 관련 조항 제공 vs RAG 끔, 관련 조항 제공 vs 고정 질의, **관련 조항 제공 vs fixed-long, fixed-long vs RAG 끔**.
  - 조건 간 차이 D_cond(t, 쌍) = |두 조건 탐지율의 차이|, 두 실행 평균 기준.
  - 실행 간 차이 D_run(t) = 다섯 조건 중 |1회차 탐지율 − 2회차 탐지율| 의 최댓값.
  - 주 지표 유형 t 와 비교 쌍 중 **하나라도 D_cond(t, 쌍) < D_run(t) 이면 3회째를 다섯 조건 모두에서 실행한다.** 3회째 결과는 그대로 포함하고 규칙을 다시 적용하지 않는다(최대 3회).
- E9-4 보조 실험: 1280x800 실행에는 포함하되 주 지표에서 제외하고, 별도로 390x844 뷰포트 실행(E9-4 15 + 대조군 30, 5조건, **반복 1회**)을 보조로 둔다.

튜닝용이 아니다.** 파일럿 결과는 모든 분석에서 제외한다. 파일럿 8페이지 중 4페이지(대조군 2, E9-3, E9-4)는 본 실험 페이지와 HTML 이 같다

### 5.2 파일럿 후 입력 수정 (`exp-freeze-e9-v3`, 2026-11-13 연구자 승인)

파일럿 대조군 위양성 4건의 원인이 입력의 자리 표시 요소였음이 로그로 확인되었다(`docs/e9_input_fix_proposal.md` a·b절).
이 요소들은 다섯 조건 모두에 같은 영향을 주는 입력이다. 그래서 기준 골격과 본문 문구만 다음과 같이 고쳤다.
정규식 규칙, 판정 프롬프트, 결함 주입 코드, 분석 계획은 바꾸지 않았다.
- **(c1) 국기 자리:** 회색 상자(`<span class="flag">`, `background:#D8D8D8`)를 실제 국기 그림
  (`<img class="flag" src="/flag.svg" alt="대한민국 국기" width="24" height="16">`, 24×16 태극기 SVG)으로 바꿨다.
  규격값(24×16)과 결정적 검증은 그대로 성립한다.
- **(c2) portal_main 본문:** `<div id="main-banner">배너</div>` 를 `<div id="main-notice">주요 소식</div>` 로 바꿨다.
  **이 수정은 "기존 템플릿 본문 그대로 재사용" 원칙에서 한 군데 더 벗어난다**
  (앞서 faq·terms·contact 본문의 로그인 링크를 지운 것에 이어 두 번째 예외).
- **(c3) 제외:** 푸터 저작권 연도 추가는 하지 않았다. 위양성 원인이 아니고, 모든 페이지의 이슈 구성을 바꾸기 때문이다.
- 같은 시드(본 실험 20261116, 파일럿 20261117)로 재생성했다. 결함 정의와 위치는 바뀌지 않았다
  (메타데이터의 page_id·subtype·body_template·defect_id·intensity·variant·injected_string·expected_failing_checks 동일).
  결정적 검증은 91/91, 8/8 통과했다. 새 문자열이 정규식 키워드를 건드리지 않음은 `tests/test_e9_v3_strings.py` 로 확인했다.
- 수정은 한 번, 재파일럿도 한 번으로 끝낸다. 재파일럿 뒤에도 위양성이 남으면 추가 수정 없이 그대로 보고한다.

## 6. 채점 규칙 (사전 지정 형식)

결과를 보기 전에 고정하고 결과를 보고 수정하지 않는다. 이슈 텍스트 = description(파이프라인 URL 접두어 제거) + 공백 + suggestion.

### 6.1 결정적 규칙 (결함별 string/regex, 언급 기반)

정규식은 대소문자 무시, 공백은 `\s*` 허용. 이슈 단위로 판정하고 유형별로 조건을 만족하는 이슈가 1건 이상이면 그 페이지에서 탐지.

| 결함 | 탐지로 보는 조건 |
|---|---|
| E9-1 | `(공식\s*배너\|배너)` 와 `(문구\|텍스트\|문장\|내용\|띄어쓰기)` 가 같은 이슈에 있음, **또는** 주입된 변형 문구(정확 문자열) 또는 규정 문구 "이 누리집은 대한민국 공식 전자정부 누리집입니다"를 인용 |
| E9-2 | `(공식\s*배너\|배너\|헤더\|header\|푸터\|footer)` 와 `(px\|글자\s*크기\|글씨\s*크기\|font-size\|굵기\|font-weight\|색상\|color\|#[0-9a-f]{6}\|높이\|height\|padding)` 가 같은 이슈에 있음 |
| E9-3 | `(signup\|회원\s*가입)` 와 `로그인` 이 같은 이슈에 있음 |
| E9-4 | `로그인` 과 `(숨\|감춰\|display\s*:\s*none\|보이지\s*않\|사라)` 와 `(768\|모바일\|작은\s*화면\|좁은\s*화면\|화면\s*너비\|media)` 가 같은 이슈에 있음 |

### 6.2 LLM 채점 (보조)

- **E9 의 주 지표는 결정적 정규식 규칙(§6.1)이고, LLM 판정은 보조다.** LLM 판정은 이슈 문구가 어떤 점검 항목을 지적하는지의 **분류**이며
  결함이 실제로 있는지의 판단이 아니다. 결함의 실재는 생성 단계의 결정적 검증(`ground_truth_e9.csv`)이 정한다.

- 모델·설정: 본 실험과 같음(Anthropic `claude-sonnet-5-5`, thinking between_tools, effort high, temperature 미지정, fallback 없음). pass1 이 주 결과, pass2 는 1회차 실행에만.
- 판정 프롬프트: `docs/e9_judge_prompt_draft.md`. **동결 대상(`exp-freeze-e9-v1`)에 포함한다.** 입력은 description 과 suggestion 만, 주입 정보 없음,
  범주는 조항 문구로 정의, 유형별 예/아니오 + 해당 없음. 연구자 결정(2026-11-12): login_destination 의 예시 "(예: 회원가입 화면)"은 넣지 않는다,
  style_spec 은 수치 없이 속성 종류로만 정의한다, banner_text 는 규정 문구 전체를 넣고 주입된 변형 문구는 넣지 않는다.
- 채점 경로(표준/배치)는 본 실험과 같은 사전 규칙(`pending_freeze_v5.md` 12항)을 따른다.

### 6.3 사람 평가 부분집합

- 표본: 고정 질의 조건과 관련 조항 제공 조건(1회차 실행)의 이슈 중 결함 유형별 5페이지(E9-1 은 1a·1b 각 3) + 대조군 10페이지 ≈ 31페이지 × 2조건의 이슈 전체.
  층화 기준은 결함 유형·강도와 대조군 여부뿐. **표본 추출 시드 20261114.**
- 평가자 2명 공동 평가, 불일치는 중재자 1명(주입 라벨·조건·채점 결과를 보지 않음). 질문: 4개 항목 예/아니오 + 해당 없음, 코드에 존재하는가, 화면에서 보이는가, 비고.
- 사람 판정을 기준 표준으로 하고 결정적 규칙과 LLM 채점을 같은 비중으로 비교한다.

### 6.4 주 지표 (아래 §6.5 한계, §6.6 해석 참고)

- 주 지표 대상(E9-1, E9-2, E9-3)의 결함 유형 × 조건별 재현율, 대조군 위양성률, 셀 단위 정밀도·특이도·균형 정확도·MCC. E9-1 은 강도 a·b 별로도 보고.
- '구조적 탐지 불가'(§3) 결함은 따로 층화해 병기.
- 조건 간 쌍 비교: exact McNemar (관련 조항 제공 vs RAG 끔, 관련 조항 제공 vs 고정 질의, 관련 조항 제공 vs fixed-long, fixed-long vs RAG 끔), Holm 보정(4개 검정).
  관련 조항 제공 vs fixed-long 이 '내용' 효과, fixed-long vs RAG 끔이 '컨텍스트 길이' 효과에 해당한다.
- 결과가 어느 방향으로 나와도 그대로 보고한다.

### 6.5 한계

- **결정적 정규식 규칙의 한계:** §6.1 규칙 중 주입된 변경 문자열(바뀐 배너 문구, `signup` 등)이나 특정 주제어 조합을 찾는 부분은
  **구체 문구 없이 일반적으로만 지적한 이슈**(예: "배너가 표준과 다르게 보인다", "로그인 동선이 이상하다")를 놓칠 수 있다(위음성).
  반대로 주제어가 우연히 함께 나온 이슈를 탐지로 셀 수 있다(언급 기반의 위양성).
- **사람 평가로 두 채점 방식을 따로 검증한다:** 사람 평가 30페이지(§6.3, 2조건)의 이슈에서 사람 판정(합의 + 중재)을 기준 표준으로
  (1) 결정적 정규식 규칙, (2) LLM 판정 각각의 이슈 단위 정확도·재현율·정밀도·Cohen's kappa 를 **따로** 계산해 나란히 보고한다.
  두 방식의 불일치 사례(정규식만 예, LLM 만 예)를 목록으로 낸다. 결과를 보고 규칙이나 프롬프트를 바꾸지 않는다.
- '구조적 탐지 불가' 결함(§3)은 시스템 입력 구조상 탐지가 어려운 경우로 층화해 따로 보고한다.
- **본문 재사용 시 로그인 링크 제거 (생성 규칙, 2026-11-13 연구자 확정):** 기준 페이지 본문은 기존 10개 템플릿의 `<main>` 을 그대로 재사용하되,
  `<main>` 안에 들어 있던 `<a href="/login">로그인</a>` 링크는 지웠다. 해당 템플릿은 faq_page, terms_page, contact_page 3개(각 1개 링크)다.
  **이유:** E9-3(로그인 링크 목적지)과 E9-4(작은 화면에서 로그인 링크 숨김)의 주입·검증 대상은 규격 헤더의 로그인 링크 하나다.
  본문에 두 번째 로그인 링크가 남으면 (i) E9-3 페이지에서 헤더 링크만 `/signup` 으로 바뀌고 본문 링크는 `/login` 그대로여서 결함이 부분적으로만 존재하고,
  (ii) E9-4 의 미디어 쿼리(`header a[href="/login"]`)가 본문 링크를 숨기지 않아 작은 화면에서도 로그인 링크가 보이며,
  (iii) "로그인 링크 = 페이지의 유일한 '로그인' 텍스트 링크"라는 결정적 검사(`login_href`)가 성립하지 않는다.
  **한계:** 이 세 템플릿의 E9 본문은 기존 testbed_200 본문과 정확히 같지 않다(링크 1개 차이). 그 밖의 본문 내용(예: portal_main 의 `<div id="main-banner">배너</div>`,
  login_page 의 `<h2>로그인</h2>`·로그인 버튼)은 바꾸지 않았으며, 이런 단어가 정규식 규칙(§6.1)의 주제어와 겹쳐 위양성 계기가 될 수 있다.
- **생성 시드:** 본 실험 91페이지 20261116, 파일럿 8페이지 20261117 (2026-11-13 연구자 확정). 파일럿 결과는 분석에서 제외한다.

### 6.6 해석

- **관련 조항 제공 조건은 RAG 에 가장 유리한 상한(upper bound) 조건이다.** 6청크에는 배너 문구 조항처럼 정답 문자열("이 누리집은 대한민국 공식 전자정부
  누리집입니다.")과 규정값(15px, #1D1D1D 등)을 직접 규정한 조항이 들어 있고, 페이지의 결함과 관계없이 모든 페이지에 결함 주제 조항을 모두 준다.
  실제 검색(고정·페이지별 질의)이 이 조항들을 찾아온다는 보장은 없으므로, 이 조건의 탐지율은 '검색이 완벽할 때 얻을 수 있는 최대 이득'으로 해석한다.
- 관련 조항 제공 vs fixed-long 의 차이는 '조항 내용'의 효과, fixed-long vs RAG 끔의 차이는 '컨텍스트 길이(와 키워드 제외 일반 조항)'의 효과로 해석한다.
- 고정·페이지별 질의 조건과 관련 조항 제공 조건의 차이는 '검색 단계가 놓친 이득'에 해당한다.
