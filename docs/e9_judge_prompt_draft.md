# E9 판정 프롬프트 초안 (승인 전, 동결 안 됨)

- 작성 2026-11-12. 연구자 승인 후 그대로 코드에 옮기고 `exp-freeze-e9-v1` 에 포함한다. 승인 뒤에는 결과를 보고 수정하지 않는다.
- 점검 기준:
  - 주입된 결함 정보 없음: 페이지 ID, 결함 ID, 주입 값(바뀐 문구, 바뀐 px·색상), 조건명을 넣지 않는다.
  - 범주는 조항 문구로 정의: 각 항목은 gov_check 점검 항목 제목과 미준수 판정 문장을 옮겨 쓴다.
  - 유형별 예/아니오 + 해당 없음.
  - 입력은 이슈의 description(파이프라인 `[URL]` 접두어 제거)과 suggestion 만.
- 채점 설정은 본 실험과 같다(claude-sonnet-5-5, thinking between_tools, effort high, max_tokens 100, temperature 미지정, fallback 없음).

## 프롬프트 전문

`<<DESC>>` 와 `<<SUGG>>` 자리에 이슈의 description 과 suggestion 이 들어간다. suggestion 이 비어 있으면 "(없음)"을 넣는다.

```text
다음은 웹페이지 자동 검수 시스템이 보고한 결함 한 건의 설명문과 제안문입니다. 아래 네 가지 점검 항목 각각에 대해, 이 설명문과 제안문이 그 항목의 위반을 지적하는지 판단하세요. 지적하면 "예", 지적하지 않으면 "아니오"로 답하세요. 네 항목이 모두 "아니오"이면 none 을 true 로, 하나라도 "예"이면 false 로 답하세요.

[점검 항목 — 디지털 정부서비스 UI/UX 가이드라인 점검 기준]
- banner_text: 공식 배너의 텍스트를 변형하지 않고 있다. 공식 배너 텍스트의 내용과 띄어쓰기는 "이 누리집은 대한민국 공식 전자정부 누리집입니다."와 동일해야 한다. 텍스트를 임의로 변형하거나 띄어쓰기를 다르게 제공했다는 지적이면 "예".
- style_spec: 공식 배너, 헤더, 푸터의 스타일을 변형하지 않고 있다. 글자 크기, 글자 굵기, 글자 색상, 배경 색상, 높이와 같은 스타일 값이 가이드라인에 정해진 값과 다르다는 지적이면 "예".
- login_destination: 로그인 링크가 항상 '로그인' 화면으로 연결되고 있다. 로그인 링크를 눌렀을 때 로그인 화면이 아닌 다른 화면으로 이동한다는 지적이면 "예".
- login_small_screen: 작은 화면 너비에서 로그인 링크를 숨기지 않고 있다. 가로 768px 이하의 작은 화면 너비에서 로그인 링크를 숨긴다는 지적이면 "예".

[설명문]
<<DESC>>

[제안문]
<<SUGG>>

JSON으로만 답하세요: {"banner_text": "예 또는 아니오", "style_spec": "예 또는 아니오", "login_destination": "예 또는 아니오", "login_small_screen": "예 또는 아니오", "none": true 또는 false}
```

## 파싱 규칙 (함께 동결)

- text 블록만 읽고 JSON 객체 하나를 찾는다. 네 키의 값이 모두 "예" 또는 "아니오"이고 `none` 이 불리언이어야 유효하다.
- `none` 이 네 값과 모순이면(모두 "아니오"인데 false, 또는 "예"가 있는데 true) 파싱 실패로 기록한다.
- `stop_reason = max_tokens` 는 파싱 실패, `refusal` 은 라벨 refusal 로 기록하고 건수를 보고한다(본 실험과 같음).
- 한 이슈가 여러 항목에 "예"일 수 있다(다중 라벨). 페이지 단위 판정은 항목별로 "예"인 이슈가 1건 이상이면 탐지.

## 연구자 결정 (2026-11-12)

- (a) login_destination 의 예시 "(예: 회원가입 화면)"은 넣지 않는다.
- (b) style_spec 은 수치 없이 속성 종류로만 정의한 현재안을 유지한다.
- (c) banner_text 는 규정 문구 전체를 포함하고 주입된 변형 문구는 넣지 않는다.
- 이 판정은 이슈 문구가 어떤 점검 항목을 지적하는지의 **분류**이며 결함 실재 판단이 아니다. E9 주 지표는 결정적 정규식 규칙이고 이 판정은 보조다.
- 이 프롬프트는 `exp-freeze-e9-v1` 동결 대상에 포함한다.

## 초안에서 연구자가 확인할 점 (위 결정으로 정리됨)

1. **login_destination 정의에서 조항의 미준수 예시 "(예: 회원가입 화면)"을 뺐다.** 조항 원문의 예시지만 E9-3 주입값(`/signup`)과 같은 단어라서
   어휘 단서가 될 수 있기 때문이다. 넣을지 정해 주세요.
2. **style_spec 은 규정 수치(15px, #1D1D1D 등)를 넣지 않고 속성 종류로만 정의했다.** 채점기는 이슈가 '스타일 값이 규정과 다르다'고 지적하는지만
   판단하면 되고, 수치를 넣으면 프롬프트가 길어지며 특정 값에 대한 어휘 단서가 생긴다. 조항 수치를 그대로 넣을지 정해 주세요.
3. **banner_text 에는 규정 문구 전체를 넣었다.** 조항이 정답 문자열 자체를 규정하므로 범주 정의에 필요하다고 판단했다(주입된 변형 문구는 넣지 않음).
4. 출력 JSON 은 약 40~60 토큰이라 max_tokens 100 을 유지했다. 시험 호출에서 잘림(`max_tokens`)이 나오면 승인 전에 보고한다.
